# 反模式统一清单（v3.8.0 汇总——回应评测 convention/antiPatternFaq 失分点）

> 收拢 README 与 SKILL.md 分散的反模式说明 + 新增易踩坑场景。上手前通读一遍。

1. **不要用写草稿的同一个模型喂 `semantic` 字段**——语义封顶信任结构化模型判定，
   自己审自己等于没审。
2. **不要把 `verified` 理解为"这篇论文支撑我的论断"**——verified 只说明来源存在、
   层级权威、登记元数据与声称一致；"句子是否真被支撑"归语义层。
3. **MCP 单次批量不要超过 50 条**——超限被拒（分批调用）。
4. **不要手改 `mcp/verify_refs.py`**——它是 scripts/ 的 sha 门禁副本，改 trunk 后跑
   sync_engine.sh。
5. **不要忽略报告中的 `needs_human_check` 旗标**——partial/unreachable 带复核指令
   是有意设计。
6. **不要在弱网把 `unreachable` 当"假引用"**——先用 `--cn`/代理重跑再下结论。
7. **不要为求星而自动化点击**（平台红线）——报告页脚的 Star/收藏链接面向人类读者。
8. **不要在 `--check-document` 里省略 `--refs`**——上下文核验需要清单核验结果做绑定。

## 触发词误触发怎么办

- 触发词（深度研究/引用核查/查证等）按语义匹配，短句如"查证一下"若被误触发，
  直接说明真实意图即可（"我只要翻译"）；不产生副作用。
- 若希望某类请求**不**触发引用核验，避免在请求中同时包含"研究/查证/引用"词与
  文献清单。
9. **不要对中英混合引用的锚词率过度报警**——跨语言（CJK vs 拉丁）混合引用的
   锚词率天然偏低（内容词不相交），上下文核验会标"疑似错配"；这是预期行为
   （清单核验侧已有跨语言守卫降 partial 转人工），按人工复核处理而非自动判死。
