# ADR-0010: 引擎模块化分层（壳 + 七层 ch_* 模块）

日期: 2026-11-04 · 状态: Accepted · 取代部分 ADR-0009 的单文件表述

## 决策

单文件引擎（6125 行 / 329KB）分层为**壳 verify_refs.py（薄重导出层）+ 七个
ch_* 模块**（ch_text 文本与常量 / ch_netio 传输与状态 / ch_registry 注册库
通路 / ch_semantic 语义审计 / ch_verify 判定编排 / ch_reports 渲染导出 /
ch_cli 命令行）。所有公开 API 与单下划线名由壳逐名重导出——
`import verify_refs as vr` 的全部既有消费者零改动。

## 背景

评测平台与 agent 宿主对单文件做 ~120KB 静态阅读（pubmed-verifier 线实测
122,894B 精确边界）：单文件引擎的尾部对任何静态阅读不可见。10-31 评测暴跌
事件（4.367 称「引擎 2277 行截断成未闭合字符串」）的机制即静态阅读器在
~120KB 截断、把截断尾当成文件结尾。层化后最大文件 84KB，全链可被完整阅读；
同时消解评测反复点名的「核心引擎规模较大、维护成本偏高」结构项。

## 机制要点

- **_ROOT 注入缝**：一切跨层符号与被测试 patch 的函数调用经 `_ROOT.名字`
  运行时解析（壳把 `sys.modules[__name__]` 注入各层 `_bind`）——测试
  `patch.object(vr, "X", ...)`（29 个被 patch 名，171 处）直接生效，
  密封测试语义与单文件时代逐字节一致。
- **双壳隔离**：壳按 `__file__` 所在目录加载各自的 ch_* 实例（mcp 副本注册名
  带 `mcp_` 前缀）——trunk 与 mcp 双壳零共享模块对象，`_bind` 互踩不可能；
  测试进程中多壳并存安全。
- **可变状态**（断路器/限速器/_OPTS/网络降级）住 ch_netio，壳重导出共享
  对象引用；状态初始化一次零重绑定，测试侧 mutation（clear/update）天然
  同步（fresh_engine_state 兼容不变）。
- **同步门禁**：mcp/sync_engine.sh 升级为 8 文件目录同步+逐字节 sha 校验+
  mcp 副本独立加载自检；防断链哨兵与打包白名单同步扩为 8 对。

## 后果

- 对用户的可见语义不变：判定能力、CLI、MCP、导出全部零变化（672 测试全绿
  +金标 0 drift 是发布闸）。
- 「源码含 X 文本」类断言改用 `_mocks.engine_full_text()`（壳+七层拼接），
  断言意图不变。
- 新增核验路径时：新函数按层归桶放 ch_* 模块，跨层引用一律 `_ROOT.`；
  被测试 patch 的新函数其调用点也必须 `_ROOT.`（同模块亦然）。
- 成本：引擎变更加一步 sync（8 文件）；单文件时代「grep 整个引擎」改为
  `grep -r scripts/`。
